# Лабораторная работа № 5. Шаблонные функции и классы

Общие требования ко всем вариантам:
1. Шаблонные классы: Реализовать как минимум один шаблонный класс, параметризованный типом данных (`template <typename T>`).
2. Нетиповые параметры: В шаблонном классе должен быть использован как минимум один нетиповой шаблонный параметр (например, template <typename T, size_t N> или int Dim). 

```text
При создании шаблонного класса вы не можете ограничиться только передачей типов данных (например, int, float, double). Вы обязаны передать как минимум одно конкретное значение (число, размер, указатель), которое будет известно еще на этапе компиляции программы

Пример:

template <typename T, size_t N>
class Buffer {
    T data[N]; // N - нетиповой параметр. Массив создается на стеке или внутри объекта.
};
```

3. Специализация: Реализовать как минимум одну полную или частичную специализацию шаблонного класса или функции для специфичного типа (например, float, double, std::complex или указателей) с изменением логики или оптимизацией памяти.

```
Специализация — это механизм, позволяющий написать отдельную, особую версию шаблонного класса или функции для конкретного типа (или набора типов), когда стандартная универсальная реализация не подходит: либо работает неоптимально, либо требует другой логики.

Полная специализация: Полностью отдельная реализация для одного конкретного типа. Все шаблонные параметры становятся известны
Частичная специализация: Вы специализируете шаблон не полностью, а только по некоторым параметрам. Остальные параметры остаются шаблонными.
```

4. Ограничение типов (SFINAE / Concepts): Использовать `#include <type_traits>` (например, std::enable_if или static_assert), чтобы запретить инстанцирование шаблона неподходящими типами (например, разрешить только арифметические типы или типы с плавающей точкой)

```
Ваш шаблонный класс или функция должны принимать только определённые типы данных и отказывать в компиляции, если пользователь попытается подставить неподходящий тип
```

5. Шаблонные функции: Реализовать как минимум две глобальные шаблонные функции (например, для вывода, сортировки, математических операций над объектами), одна из которых должна иметь явную специализацию.

6. Дружественные функции: Реализовать дружественную шаблонную функцию (или дружественный шаблонный класс) для доступа к закрытым полям

7. Статические члены: Реализовать статический член-данные в шаблонном классе (например, подсчет созданных объектов данного типа или учет выделенной памяти) и статическую функцию для доступа к нему

8. Файловый ввод/вывод: Данные об объектах хранить в текстовом или бинарном файле. При запуске тестов начальная информация о 10 объектах должна считываться из файла.

## Варианты


### Вариант 1. Динамический массив для математических векторов (MathVector)
Описание: Разработать шаблонный класс динамического массива MathVector<T, InitialCapacity> для хранения координат точек или компонент векторов в вычислительных задачах.
Требования:
Нетиповой параметр InitialCapacity задает начальный размер буфера.
Реализовать операции: сложение, вычитание, скалярное произведение.
Специализация для T = double: использовать векторизацию или специфичные функции точности.
Статический член: общий объем памяти (в байтах), выделенный всеми векторами данного типа T.
Запретить создание векторов из неарифметических типов.

### Вариант 2. Умный указатель с подсчетом ссылок (SharedPtr)
Описание: Реализовать собственный шаблонный класс SharedPtr для управления динамически выделяемыми массивами данных.
Требования:
Реализовать механизм подсчета ссылок.
Шаблонная функция make_shared<T>(args...) для безопасного создания.
Специализация для массивов SharedPtr<T[]> с корректным вызовом delete[].
Использование std::enable_if для запрета создания указателя на void или функции.
Статический член: текущее общее количество активных управляемых объектов в программе.

### Вариант 3. Решение систем линейных алгебраических уравнений (СЛАУ)
Описание: Создать шаблонный класс, инкапсулирующий матрицу коэффициентов и вектор свободных членов для решения СЛАУ фиксированной размерности.
Требования:
Шаблонный класс LinearSystem<T, N>, где N – количество уравнений/неизвестных (size_t).
Специализация: LinearSystem<double, 3> с реализацией метода Крамера или специфичной оптимизацией для 3x3 систем (развёрнутые формулы).
Ограничение типов: static_assert(std::is_floating_point_v<T>, "Only floating point types are allowed for LinearSystem");.
Глобальные шаблонные функции: solve и printSystem. Функция solve должна иметь явную специализацию для LinearSystem<double, 3>.
Дружественная функция: friend void scaleEquation(LinearSystem<T, N>&, size_t eqIndex, T factor);.
Статический член: totalSystemsSolved и функция getTotalSystemsSolved().
Файловый ввод/вывод: Считать из файла 10 систем уравнений (матрица A и вектор B).

### Вариант 4. Тензор ранга N (Tensor)
Описание: Шаблонный класс Tensor<T, int Rank, size_t Dim> для представления тензоров (например, тензора напряжений или метрического тензора).
Требования:
Нетиповые параметры: Rank (ранг) и Dim (размерность по каждому измерению).
Реализовать доступ к элементам через рекурсивные шаблонные операторы operator()(indices...).
Шаблонная функция свертки тензора.
Специализация для Rank = 1 (вектор) и Rank = 2 (матрица) с оптимизированными методами.
Запретить создание тензоров с Rank < 1 или Dim == 0.

### Вариант 5. Облако точек (PointCloud)
Описание: Шаблонный класс PointCloud<T, int Dimensions> для хранения пространственных данных (например, координат частиц в 2D или 3D поле).
Требования:
Нетиповой параметр Dimensions (обычно 2 или 3).
Внутренняя структура точки должна быть оптимизирована (например, std::array<T, Dimensions>).
Шаблонная функция вычисления центроида облака.
Специализация для Dimensions = 3: добавить функцию вычисления векторного произведения.
Статический член: суммарное количество точек во всех созданных облаках.

### Вариант 6. Кольцевой буфер (RingBuffer)
Описание: Шаблонный класс RingBuffer<T, size_t Capacity> для хранения истории состояний системы (например, последних значений температуры или давления в узле сетки).
Требования:
Нетиповой параметр Capacity задает фиксированный размер буфера.
Реализовать методы push, pop, front, back.
Шаблонная дружественная функция для применения математической операции (например, вычисления скользящего среднего) ко всем элементам буфера.
Специализация для тривиально копируемых типов (std::is_trivially_copyable): использование memcpy для оптимизации сдвига индексов.
Статический член: максимальная зафиксированная емкость среди всех созданных буферов.

### Вариант 7. Геометрические примитивы (Полигоны)
Описание: Реализовать класс для представления многоугольников с фиксированным числом вершин, используемых в задачах вычислительной геометрии или визуализации.
Требования:
Шаблонный класс Polygon<T, Vertices>, где Vertices – количество вершин (size_t, >= 3).
Специализация: Polygon<double, 4> (Четырёхугольник) с оптимизированным вычислением площади (например, развёрнутая формула Гаусса) и проверкой на выпуклость.
Глобальные шаблонные функции: calculateCentroid и printPolygon. Функция printPolygon должна иметь явную специализацию для Polygon<double, 4>.
Дружественная функция: friend void translate(Polygon<T, V>&, T dx, T dy);.
Статический член: totalPolygonsDefined и функция getTotalPolygonsDefined().

### Вариант 8. Сенсорные данные IoT (скользящее окно)
Описание: Реализовать класс для хранения последних N показаний датчика (скользящее окно), поддерживающий быструю фильтрацию данных.
Требования:
Шаблонный класс SensorReadings<T, WindowSize>, где WindowSize – размер окна (size_t).
Специализация: SensorReadings<bool, WindowSize> с оптимизацией памяти (битовая упаковка, bit-packing), так как булевы датчики (например, движения) занимают 1 бит.
Глобальные шаблонные функции: computeMovingAverage и printReadings. Функция printReadings должна иметь явную специализацию для SensorReadings<bool, W>.
Дружественная функция: friend void addReading(SensorReadings<T, W>&, T value);.
Статический член: totalSensorsActive и функция getTotalSensorsActive().

### Вариант 9. Tuple обобщённый — кортеж переменного размера
Описание: Реализовать собственный аналог std::tuple<Ts...> — кортеж, хранящий значения разных типов. Демонстрация работы с variadic templates и рекурсией шаблонов.
Требования:
Шаблонный класс Tuple<Ts...> с variadic templates.
Реализация через рекурсивное наследование (или рекурсивную структуру).
Функции: get<N>(tuple), tuple_size, tuple_cat.
Шаблонная функция make_tuple(args...) для автоматического вывода типов.
Специализация для Tuple<> (пустой кортеж) — базовый случай рекурсии.
Статический счётчик: число созданных кортежей каждого размера.
Дружественная функция для вывода в поток.

### Вариант 10. LRU Cache<K, V, Capacity> — кэш с вытеснением
Описание: Шаблонный класс LRUCache<K, V, size_t Capacity> — кэш, хранящий последние использованные элементы. При переполнении вытесняет наименее давно использованный (Least Recently Used).
Требования:
Нетиповой параметр Capacity — максимальное число элементов.
Реализация через std::list + std::unordered_map (или собственная).
Методы: get(key), put(key, value), size(), clear().
Шаблонная функция для массового заполнения кэша.
Специализация для V = std::string: оптимизация перемещения строк.
Статический счётчик: число промахов (cache miss) и попаданий (cache hit).
Дружественная функция для вывода состояния кэша.
