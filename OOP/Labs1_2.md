# Лабораторная работа №2 по ООП
Срок сдачи 10.10.2026

## Постановка задачи 

Необходимо разработать программу, моделирующую некоторую предметную область (согласно варианта) с использованием классов C++.  
Программа должна содержать как минимум один самостоятельно разработанный класс.  
Класс должен представлять **целостную логическую сущность**, а не просто набор несвязанных переменных.  

## Обязательные требования

Разрабатываемый класс должен удовлетворять следующим требованиям:
1. Класс должен содержать не менее **4 полей различных типов**;
2. Необходимо использовать как минимум три различных типа данных;
3. Все поля должны находиться в секции private;
4. Доступ к состоянию объекта должен осуществляться через его публичный интерфейс.
5. Необходимо реализовать конструктор, позволяющий создать объект без аргументов. Он должен задавать объекту корректное начальное состояние
6. Необходимо создать минимум один параметризованный конструктор.
7. Класс должен содержать не менее **трёх способов создания объекта**
8. Минимум один конструктор необходимо реализовать с использованием списка инициализации
9. Для данных, которые необходимо читать вне класса, требуется реализовать методы получения значений
10. Методы, не изменяющие объект, должны быть объявлены как
11. Класс должен иметь минимум **три метода, изменяющих состояние объекта**
12. Недолжно быть бессмысленых setter-методов. (Например для банковского счета недолжно быть метода setBalance(), логичнее назвать его deposit())
13. Класс должен обеспечивать корректность собственного состояния (Например цена на товар не должна быть отрицательная)
14. Перед реализацией определить минимум **три условия корректности объекта**. (см. пункт 13)
15. Должен быть реализован метод вывод информации
16. Необходимо явно определить деструктор. На данном этапе деструктор не обязан освобождать динамическую память. Его задача в данной случае продемонстрировать понимание момента завершения времени жизни объекта
17. В функции `main()` необходимо создать минимум **три объекта одного класса**
18. Объекты должны создаваться с использованием различных конструкторов.
19. Необходимо продемонстрировать, что состояние одного объекта не влияет на состояние другого.
20. Рекомендуется разделить программу на три файла:
```text
ClassName.h
ClassName.cpp
main.cpp
```
21. Добавить в класс **статистический счётчик количества существующих объектов**.

## Этапы выполнения работы:

### №1 Определить сущность согласно варианту.

Ответить на вопросы:

1. Что представляет собой объект?
2. Какие данные характеризуют объект?
3. Какие действия можно выполнять с объектом?
4. Какие состояния объекта являются недопустимыми?

### №2 Проектирование класса

Составить таблицу.

| Элемент | Описание |
|---|---|
| Имя класса | название создаваемого типа |
| Поля | состояние объекта |
| Конструкторы | способы создания объекта |
| Методы чтения | получение информации |
| Методы изменения | изменение состояния |
| Инварианты | условия корректности |

### №3 Обязательное тестирование

Недостаточно продемонстрировать только правильные действия.
Необходимо проверить реакцию класса на **некорректные операции**.
Функция `main()` должна представлять собой тест класса.

Она должна содержать минимум следующие этапы:
1. Создание объектов
2. Вывод начального состояния
3. Выполнение корректных операций
4. Выполнение некорректных операций
5. Повторный вывод состояния (Необходимо показать, что объект сохранил корректное состояние)
6. Проверка независимости объектов (Изменить один объект и показать, что состояние остальных объектов не изменилось)


## Вариант 1. Банковский счёт

Создать класс:

```cpp
BankAccount
```

Поля:

```text
номер счёта
имя владельца
баланс
состояние счёта
```

Пример состояния:

```cpp
bool active;
```

Реализовать операции:

```cpp
deposit()
withdraw()
block()
unblock()
getBalance()
print()
```

Ограничения:

- сумма пополнения должна быть положительной;
- сумма снятия должна быть положительной;
- нельзя снять сумму больше баланса;
- нельзя выполнять операции с заблокированным счётом.
