## Базовые знания по git

Репозиторий можно хранить локально (на вашем компьютере, например, в папке с проектами) или использовать удаленные веб-сервисы для хранения, такие как GitHub.

При использовании GitHub рекомендуется создание SSH-ключа для безопасного подключения с вашего компьютера. При работе только с локальным репозиторием создание SSH-ключа не требуется.

### Создания SSH ключа

SSH-ключ нужен для безопасной аутентификации и связи вашего компьютера с удаленным репозиторием на GitHub.

#### Сгенерируйте ключ:
```ssh-keygen -t ed25519 -C "your_email@example.com"```

(Замените "your_email@example.com" на ваш реальный email, который используется для GitHub)

Эта команда генерирует пару ключей: закрытый (private key) и открытый (public key).

#### Добавьте открытый ключ на GitHub:

1. Перейдите в Settings → SSH and GPG keys  
2. Скопируйте содержимое вашего публичного ключа. Его можно найти в файле `~/.ssh/id_ed25519.pub`  
3. Для этого в командной строке выполните:

```clip < ~/.ssh/id_ed25519.pub``` - (Эта команда скопирует ключ в буфер обмена в Windows) 

Или выведите содержимое файла командой cat и скопируйте его вручную:

```cat ~/.ssh/id_ed25519.pub```

4. Вставьте ключ в соответствующее поле на GitHub.  

#### Проверка подключения

При первом подключении к GitHub через SSH вы можете увидеть запрос о подтверждении подлинности хоста:

*The authenticity of host 'github.com (255.255.255.255)' can't be established.
ED25519 key fingerprint is SHA256:+D**************isF/zLDA0zP**************qU.
Are you sure you want to continue connecting (yes/no/[fingerprint])?*  
Наберите yes и нажмите Enter. Это добавит GitHub в список доверенных хостов на вашем компьютере.

Проверить правильность настройки можно командой:  
```ssh -T git@github.com```  
Если всё настроено правильно, вы увидите сообщение:  
*Hi UserName! You've successfully authenticated, but GitHub does not provide shell access.*

Если после настроек при вводе команды ```git push``` требуется ввод логина и пароля,   необходимо проверить URL вашего репозитория  
```git remote -v```, скорее всего там будет ссылка https:  
origin https://github.com/UserName/your-repo.git (fetch)  
origin https://github.com/UserName/your-repo.git (push)  
Необходимо заменить её на SSH:  
```git remote set-url origin git@github.com:UserName/your-repo.git```
### Работа с локальным репозиторием

#### Инициализация репозитория:

```git init```  - 
Выполните эту команду в папке, где вы хотите создать репозиторий. Она создаст скрытую папку .git для хранения всей истории и метаданных проекта.

#### Добавление файлов в индекс (staging area):

```
git add name.txt    # Добавит конкретный файл
git add .           # Добавит все новые и измененные файлы в текущей папке
git add --all       # Добавит ВСЕ новые и измененные файлы в репозитории
```
Эти команды подготавливают снимок состояния файлов для следующего коммита.

#### Создание коммита (сохранение состояния):

```git commit -m "Текст вашего сообщения"``` -
коммит сохраняет текущее состояние проиндексированных файлов в истории репозитория.

### Связывание с удаленным репозиторием и отправка изменений

#### Добавление удаленного репозитория:

```git remote add origin "addr_for_repository"```

(Замените "addr_for_repository" на SSH- или HTTPS-адрес вашего репозитория на GitHub) Команда git remote add связывает ваш локальный репозиторий с удаленным сервером.

#### Отправка изменений на сервер:
```git push -u origin main``` - 
Флаг -u ( --set-upstream) связывает вашу локальную ветку с удаленной, чтобы в дальнейшем можно было использовать просто git push.
После первоначальной настройки для отправки изменений будет достаточно команды:  
```git push```

### Основной рабочий цикл
После настройки для внесения изменений в проект и их отправки на GitHub обычно используется последовательность из трех команд:
```
git add .                     # Подготовить к сохранению все измененные файлы
git commit -m "Сообщение"     # Сохранить изменения в истории локально
git push                      # Отправить изменения на удаленный сервер (GitHub)
```
